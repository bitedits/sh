==== WHAT THIS LAYER COULD NOT SIZE ====
  Nothing: every pool the header declares now carries a capacity read out
  of jpl_caps_table.  The last gap was the word slab.  sh_jpl.v §1 added
  MAX_WORDS on 2026-10-05 as the sum 2*MAX_STACK + 2*MAX_ENV + 2, whose
  tree half and environment half are PROVED (§7.1 cmd_fits_words from
  cmd_words <= 2*cmd_count; §5 benv_words_le) and whose expanded-copy half
  is the NAMED OBLIGATION "one live frame per source node" — so the header
  allocates against a decomposition with one recorded debt, not a guess,
  and jpl_check_words_is_the_named_sum pins the C macro to that sum.
  Cost of the decision, measured: the slab is 33416.0 KiB, which is 33286 indices —
  16642 cells per space x 2 spaces, each space reserving its own index 0 —
  x 1028 bytes per cell, and it dominates every other pool.  The per-cell size is
  MAX_WORD uint32 codes; narrowing them needs a proved `code < 256`, which
  sh_concrete.v §1 only intends — see JPL.md §6's follow-on note.

  Each pool is ONE array of 2 intervals, so 2f's declared-pool grep still
  reads 8 pools: the split is inside the index domain, not in the name count.  A space
  reserves its own index 0, so a pool serves the artifact's cap cells PER SPACE, and
  `jpl_pools_swap()` — one global, one writer — says which space is current.  That
  pointer is absolute and is read against the current interval, so `reset` rewinds to
  the current base + 1u rather than to 1u, and `peak` counts a region's cells instead of
  remembering a high-water index.
  Reclamation is at REGION granularity: a reset returns every cell at once,
  because a per-cell free needs the reachability rule §6.5's ii-b-2 owns before it is
  safe, not a function.  A reset does not clear cells, and `is_live` is the guard rail
  that makes a handle carried across one — or across a swap — observable (§6.7: after a
  swap a handle from the previous interval reads dead while sitting BELOW the current
  `next`, which is the case §6.6's `h < next` could not distinguish).  `peak` is the
  quantity decision 4 said no walk over the artifact's text could produce — a run
  measures it.  With no kernel that allocates yet, every peak in this tree is 0: this is
  the instrument, not the number, and the gate prints that zero as one.

==== THE THREE NON-DERIVED CHOICES ====
  1. pooled types            cmd, frame — from sh_jpl.v §1's cap comments, each with
                             cmd -> jpl_cmd_pool: 4096 cells per space x 2 spaces, sized from JPL_MAX_CMD
                             frame -> jpl_frame_pool: 8192 cells per space x 2 spaces, sized from JPL_MAX_STACK
                             (the two halves are cross-checked: naming a type pooled without
                             capping it is a refusal, not a silent fall-through to a by-value
                             layout).  Every other vocabulary type is by value and needs no
                             capacity
  2. list pool sizing        pair(text,text) -> JPL_MAX_ENV, frame list -> JPL_MAX_STACK,
                             every other list kind -> JPL_MAX_LIST
  3. headroom factor         2.  §6.7 paragraph 4 reads it as a NUMBER OF
                             INTERVALS, not slack, so it is now the spaces of every
                             pool's array: one holds the live set, one receives the
                             copies a step boundary builds before releasing it.  That
                             reading does not discharge the proof JPL.5-B.3 still
                             owes — that the live set is bounded by the cap — it only
                             says what a factor of 1 would mean (no to-space, so no
                             copying collection at all).  Stated here so it is not
                             silently absorbed into an array dimension.
